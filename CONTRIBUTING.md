# Contributing to Lorealm

Thanks for your interest in contributing! 🎉

## How can I contribute?
### Reporting Bugs
- Search existing issues first to avoid duplicates.
- Open a new issue using the bug report template.
- Include steps to reproduce, expected vs. actual behavior, and your environment (OS, version).

### Suggesting Features
- Search existing issues first to avoid duplicates.
- Open a new issue using the feature request template.

### Your First Contribution
- Look for issues labeled `D-Easy` or `M-Help-Wanted`.

## Development Setup
See [Building from Source](https://docs.lorealm.app/getting-started/installing/#building-from-source) in the documentation, along with the listed prerequisites above.

## Pull Request Process
1. Fork the repo and create a branch from `staging` (e.g. `fix/login-bug`).
2. Make your changes and add tests where relevant.
3. Make sure tests and linting pass (`cargo ci`, `make lint`, `make check`).
4. Update documentation if behavior changes.
5. Open a PR with a clear description and link related issues (`Closes #123`).

## Style Guide
- Make sure all files are formatted before submitting (`cargo fmt`, `make format`)
- Follow the AI Guidelines below.

## AI Guidelines
While the use of AI tools is accepted, we have some limitations:
- No AI-generated prose (Documentation, PRs, comments, etc.).
- No unsupervised AI code; you should understand the code you send in.
- Disclosure: Every PR that uses AI should disclose how it's used.
- Maintainers reserve the right to close PRs they deem low quality, overly large, or not in line with these guidelines.
